GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat では、作業がローカルでリアルタイムに進むため、各ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または取り消し、フォローアップのプロンプトで会話を調整しながら、エディターを離れずに作業を続けられます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッションの途中でエージェントに指示し、ハイ コントラストに加えてライト モードも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中、デザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライト モードへの切り替えも追加してほしいとのことです。新しい会話を最初から始めずに、既存のセッションに追加の作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案された編集を確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール操作を確認します。ファイルの読み取りと編集、実行を求められたターミナル コマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業してもらいます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ツールの使用許可を求められた場合 (ターミナル コマンドの実行など)、エージェントは一時停止して **Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に、実施した変更の概要が表示されます。

## エージェントにライト モードも依頼する

ハイ コントラスト モードを実装できたので、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けると、エージェントは前の作業のコンテキストを保持しています。変更したコンポーネント、スタイルの方針、local storage の使い方などを引き継げます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前に行った変更を確認し、ライト モードの追加を提案します。
3. ハイ コントラストのときと同じように、新しい編集を確認して、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合 (たとえば、気に入らない方法でトグル UI をリファクタリングする場合) は、チャット入力欄の隣にある **Stop** ボタンで停止し、補足のプロンプトを送信します。

> [!TIP]
> 進行中のセッションに指示を追加するほうが、最初からやり直すよりも速くなります。フォローアップ プロンプトで調整を依頼できます (例: 「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」)、方向を修正できます (例: 「3 つ目のトグルは追加せず、既存の設定パネルにライト モードを追加してください」)、範囲を広げることもできます (例: 「両方のトグルにキーボード ショートカットも追加してください」)。

## 作業ファイルを確認する

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指示したアクセシビリティ パターン、ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持などが反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode で、進行中のセッションを監視して方向を調整しました。各ファイル編集を確認し、変更を承認または取り消し、コンテキストを保ったままフォローアップのプロンプトを送って作業を拡張しました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- フォローアップのプロンプトを使って、進行中のセッションの方向を調整しました。

[次のレッスン][next-lesson]では、アクセシビリティの変更をプル リクエストとして公開し、このラボでローカル カスタム エージェントが行った変更をレビューします。
